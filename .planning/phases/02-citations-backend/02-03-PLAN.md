<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /chat/stream | The request body (`question`, `document_ids`, `history`) is Pydantic-validated by `ChatRequest`; `document_ids` flows through to the Chroma `$in` filter. |
| LLM output -> streaming path | The provider's raw token stream is untrusted; it passes through `CitationStreamParser` before reaching `{token:...}` SSE events. |
| parser/provider exception -> client | An exception inside the streaming generator must not leak a stack trace to the client. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | I (Info Disclosure) | streaming try/except in stream_answer_with_graph | mitigate | The existing `try/except` is preserved and now also wraps `parser.feed()`/`flush()`; on any exception it `print()`s `type(e).__name__: {e}` server-side and yields only a generic "temporarily unavailable" token — no stack trace, no chunk text, no API key reaches the client (D-08 / RESEARCH Security Domain). |
| T-02-03-02 | T (Tampering) | document_ids filter regression | mitigate | SC5 test extension asserts every cited chunk's `document_id` is inside the requested `document_ids` filter — a refactor that drops the filter parameter fails the test loudly before reaching a user. |
| T-02-03-03 | D (Denial of Service) | DoneEvent validation failure path | mitigate | A `ValidationError` on the assembled `done` payload is caught, the offending marker dropped + `print()`-logged, and the stream completes — a parser bug degrades the payload instead of 500ing or hanging the stream. |
| T-02-03-04 | S (Spoofing) | crafted `[N]` markers in LLM output | mitigate | Marker resolution is positional against `filtered_sources` and the client contract is chunk_id-based; an injected out-of-range marker is stripped (D-03) and cannot spoof a citation to a chunk that was not retrieved for this request. |
</threat_model>
