<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → factory | `LLM_PROVIDER` is read from the process environment (untrusted-ish — developer-controlled on a single-user desktop tool) and switches the factory branch. |
| config → provider | `GROQ_API_KEY` is read from config into `GroqProvider`; it must never reach logs or exception messages. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | T (Tampering) | `get_provider()` factory | mitigate | `get_provider()` switches on an explicit allow-list (`"groq"` only in v1); any unknown value raises `ValueError` rather than falling through — no arbitrary-provider injection. |
| T-02-01-02 | I (Info Disclosure) | `GroqProvider` exception handling | mitigate | Exception logs use `f"{type(e).__name__}: {e}"` only (existing safe pattern); `GROQ_API_KEY` is never interpolated into a log line or exception message. |
| T-02-01-03 | D (Denial of Service) | provider instance cache | accept | Cache is a process-local dict keyed by provider name; bounded by the tiny allow-list. No unbounded growth. |
| T-02-01-04 | I (Info Disclosure) | added providers (future) | transfer | Privacy LOCKED constraint: any future `get_provider()` branch MUST be a no-train endpoint (Anthropic / OpenAI zero-retention / Groq per ToS). v1 ships Groq-only; constraint documented for future phases. |
</threat_model>
