Normalization regex (RESEARCH line 170 / AI-SPEC line 265):
`r"\[\s*(?:Source\s+)?(\d+(?:\s*,\s*\d+)*)\s*\]"` — captures `[N]`, `[Source N]`, `[1, 2]`, `[ 3 ]`.

Quote extractor (RESEARCH §"Supporting-Quote Extraction", PATTERNS §quotes.py) — USE
stdlib `difflib.SequenceMatcher` (rapidfuzz is NOT installed — RESEARCH correction):
```
from difflib import SequenceMatcher
def best_quote_span(chunk_text: str, answer_span: str) -> tuple[int, int, float]:
    sm = SequenceMatcher(None, chunk_text, answer_span, autojunk=False)
    match = sm.find_longest_match(0, len(chunk_text), 0, len(answer_span))
    start, end = match.a, match.a + match.size
    score = match.size / max(len(answer_span), 1)
    return start, end, score
```
`autojunk=False` is load-bearing. Returned span re-slices `chunk_text[start:end]` to
a guaranteed verbatim substring.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output → parser | The raw token stream from the LLM is untrusted text; the parser runs a regex over it and emits cleaned tokens to the client. |
| chunk text → quote extractor | `chunk_text` originates from uploaded-PDF content (untrusted) but is only used as the haystack for substring extraction — no eval, no execution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | D (Denial of Service) | parser normalization regex | mitigate | The marker regex `\[\s*(?:Source\s+)?(\d+(?:\s*,\s*\d+)*)\s*\]` has no nested quantifiers over overlapping classes — no catastrophic-backtracking ReDoS path. The `\d+(?:\s*,\s*\d+)*` group is linear. Keep the regex exactly as specified; do not add `.*` or nested optional groups. |
| T-02-02-02 | T (Tampering) | crafted marker text in LLM output | mitigate | A crafted `[999]` or `[Source 999]` cannot forge a citation: resolution is a positional lookup bounded by `len(filtered_sources)`; out-of-range markers are stripped + logged (D-03). The client contract is chunk_id-based, so injected marker numbers cannot point at chunks that were not retrieved. |
| T-02-02-03 | I (Info Disclosure) | D-03 print() logging in parser/quotes | mitigate | Log lines carry only marker numbers, source counts, and fuzzy scores — never full `chunk_text`, never API keys (RESEARCH Security Domain). |
| T-02-02-04 | I (Info Disclosure) | quote extractor on PDF content | accept | `best_quote_span` only slices `chunk_text`; the quote returned is content the user already uploaded and is entitled to see. Single-user desktop tool. |
</threat_model>
